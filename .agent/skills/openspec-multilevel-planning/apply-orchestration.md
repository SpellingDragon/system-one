# 执行编排手册（阶段 6 用：多 agent 并发实施 + 验收评审）

规划落定后的 apply 阶段 SOP。核心信条：**编排者司集成与裁决，agent 司域内实现；凡报必验、凡修必回归；子 agent 的完成情况必须协议化核查，未完成/遗漏者归因后修计划再重派；执行期发现的计划缺口必须回写。**

## 一、环境预备（派发前 15 分钟，缺一勿发）

1. 解释器达标：系统 python 不满足项目 requires 时寻 brew/conda 新版。
2. venv + 轻装先行：先装 pytest/ruff 等轻包即派纯逻辑域；重包随后。
3. **预建包骨架**：按规划目录建 `__init__.py` 空文件再 `pip install -e .`——否则 editable 映射不到新增顶层包。
4. 探设备能力与关键库版本，作为"环境情报"随令下传。

## 二、Agent 派发模板（prompt 八要素）

```
① 变更定位：一级 change 名 + 二级子变更目录路径（CLI 不识别嵌套，须显式给路径）
② venv：所有 python/pytest 命令的绝对路径
③ 必读四件套：proposal/design/tasks/spec（+项目注释规范章节）
④ 已就绪资产情报：前序域的真实产物路径与可 import 的接口签名——免 agent 重探
⑤ 写入白名单：精确到文件/目录；明令"不动他域文件、禁 git commit/checkout"
⑥ 验证纪律：每条孙任务验证命令 exit 0 才勾 [x]；训练类 = run-id+指标存在；
   汇报须附逐条验证输出摘要（passed 数/run-id/关键数字）——供编排者核查的原始凭据
⑦ 质量门自检：check_comments/ruff 本域必须绿
⑧ 探针域加"据实回退"分支：失败按 spec 回退场景执行并原样记录报错（这是交付物）；
   附参考源码路径（如 tilelang 主仓）供 API 考证
```

任务须自含完成判据（每条孙任务的验证命令即判据）——理想情况下 agent 凭判据自足完成；判据不清的任务先修计划再派。

**纪律**：改文件与跑验证不得与 Write/Edit 同批并行——本系列三次竞态误判皆源于此（测试跑在修正前的旧码上）。

## 三、波次推进 SOP（每波之间编排者五步）

```
派发（同波全并发）→ ① 完成度核查（第四节四查，域清零才算完）→ ② 集成验证：
全量门禁复跑（agent 各自绿 ≠ 整体绿，并发中间态会产生误报，只认最终态）→
③ 跨域情报裁决：agent 带回的他域缺陷报告，先实证真伪（读码/复现），确真则由
编排者修复（唯一能越域者），附回归用例 → ④ 一级账目勾选：每行附凭据摘要 →
⑤ 情报下传：本波产物路径与接口签名写进下一波 prompt 的要素④
```

## 四、完成度核查与重派发协议（每波必做，域清零为止）

理想态是 agent 凭判据自足完成；现实态必须协议化核查。**四查**：

### 查 1：勾选真实性
- 逐勾选项复跑其验证命令（成本高则抽查关键项 + 全量测试兜底）；**勾了但验证不过 = 假勾**，按未完成处理并记录（假勾两次以上的域，重派 prompt 加"逐条粘贴验证输出"要求）。
- **未勾但有产物**：agent 忘勾或验证未跑——复跑验证后替其补勾（如实注明），或打回。

### 查 2：产物盘点
- 白名单预期文件 vs 实际落地（`git status` / `find`）；计划声明的产物类型（测试文件 / run 目录 / 配置 / README 段）逐一存在。
- spec scenarios ↔ 测试的映射存在性：spec 写了场景而测试文件里找不到对应者 = 遗漏。

### 查 3：数字溯源
- agent 汇报的关键数字（N passed / run-id / 指标 / 编译键）逐个 grep 或复跑核验；对不上的以实测为准并追记。

### 查 4：遗漏检测（计划 vs 实况）
- 域 tasks 全孙任务 vs 勾选状态：未勾项归类——计划内标注"可延后"的放行，其余为遗漏。
- 对照**目标-任务覆盖矩阵**复查本域：是否暴露计划没写的任务（触发第六节回写）。

### 归因与重派（决策树）

```
未完成/遗漏 → 归因三型：
  a. agent 未完成（空返/部分/假勾）      → 重派
  b. agent 做错（验证过但逻辑错）         → 域内错重派修复；跨域错走情报裁决（编排者修）
  c. 计划缺任务（覆盖性缺口）             → 先回写计划（第六节）再派新任务
重派 prompt 三型：
  · 复跑验证型（空返但有产物）："逐条复跑验证而非重做"——防重复劳动与覆盖
  · 补缺型（部分完成）："以下 N 条未完成/假勾，已有产物在 X，只补缺不重做"
  · 修复型（做错了）：附缺陷证据（traceback/对拍数据/失败测试名），限定修复范围与回归要求
重派后同样过四查，直至该域清零；同一域重派 ≥3 次仍不清 → 升级处理：拆小任务或
编排者亲自完成该残余（并在 run notes 记录升级原因）
```

## 五、空返处置（归因 a 的特例，单列以快查）

1. **先验工作区实况再定重做**：查目标文件是否已落地、tasks 是否已勾、测试是否真绿。
2. 重派 prompt 改令"逐条复跑验证而非重做"——空返 agent 往往已完成工作。
3. 仍空返且无产物：拆小任务范围再派。

## 六、计划缺陷回写（执行期的规划复盘，防复发）

执行期暴露的计划缺口（本系列实证五类：目标无任务承载/消费者漏枚举/档位覆盖不全/性能主张无基准/mock 冒充路径验证）按固定动作回写：

1. **定位类别**：对照 skill 反模式 R10–R14 归类。
2. **补计划**：在对应子变更 tasks.md 补孙任务并标注来源（如"【P1 教训回写】"）；涉跨域语义的（如 parity 轴悬空）在 proposal/一级文档补边界声明。
3. **补检查**：若该类别 review-checklist 尚无对应检查项，回写 skill 的 review-checklist.md（覆盖性检查节）。
4. **记证据**：返工的根因与代价写入当前 run 的 notes（哪一步暴露、若规划期抓住能省多少）。

## 七、收尾 F 流程（一级直管）

1. F1 全量门禁（CPU + 设备档，修复后总回归）。
2. F2 DoD 核验——用项目自己的 run 工具立收尾 run（吃自己狗粮），逐条附证据；编排者笔误以追加更正行处理（防重写机制下原行不删）。
3. F3 README 导览表（实现↔手册↔runs 三向映射，run-id 逐字符核对）。
4. F4 `openspec archive <name> --yes`；归档后勾 F4。

## 八、验收评审双路法（实现完成后）

- **代码层**：派 CodeReview 子代理（唯一一个），prompt 给足：范围界定方式（git status/diff）、项目契约清单、假绿测试/数值正确性/安全为重点、Critical/Major/Minor 分级输出。
- **运行层**（编排者亲验，不可代理）：
  - 全量 CPU 门 + 设备门复跑；
  - repro 脚本复跑取**新 run-id 链**（证明可重复，非复用旧证据）；
  - runs 逐 run 核账：config.commit 实取 git HEAD、metrics step 单调、notes 结论行齐；
  - 数字溯源抽查：报告关键数字回到对应 run 指认；
  - 性能数字必含预热后热态（编译/首访开销排除，冷启动数据不进决策表）。
- **修复纪律**：发现即修；修测试不猜常量名（import 生产侧常量）；造"裸数据"优先复制真产物抹键；修复若引入新败，取 traceback 实证再正法——评审-修复-回归闭环中自己也会踩坑，如实记录。

## 九、执行期反模式（R6–R9 详版）

- **R6 空返即重做**：agent 空返 ≠ 未完成；重做前先验工作区，重派令改"复跑验证"。
- **R7 信汇报不复验**：agent 报的数字/绿灯必须编排者 grep 校账与全量复跑确认。
- **R8 跨域缺陷无人认领**：agent 白名单不能越域修他域 bug——这类情报恰是并发执行的涌现价值，编排者是唯一裁决与修复点，修必附回归用例。
- **R9 集成只在最后**：每波之间就做集成验证，并发中间态的失败要在当波定位。
